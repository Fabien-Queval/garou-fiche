# W20 — Test d’affinité tribale
## Brief UX/UI et intention narrative

### 1. But de l’expérience

Cette étape de création de personnage ne doit **pas attribuer automatiquement une Tribu**.

Le questionnaire sert uniquement à détecter les philosophies tribales avec lesquelles le personnage semble le plus en résonance.

À la fin :

- les 13 Tribus restent visibles et sélectionnables ;
- quelques Tribus sont mises en avant comme affinités naturelles ;
- aucune Tribu n’est cachée ou verrouillée par le résultat psychologique ;
- le joueur lit les descriptions, découvre leurs cultures et leurs Dons possibles ;
- le joueur effectue lui-même son choix final.

Le message implicite doit être :

> « Voilà celles qui semblent te reconnaître. Mais c’est encore à toi de décider laquelle tu veux rejoindre. »

L’expérience doit donc éviter l’effet « test de personnalité qui décide qui tu es ».

Le questionnaire conseille.  
Le joueur choisit.

---

# 2. Place dans le parcours narratif

Le site commence comme une interface humaine, froide, administrative, presque corporate.

À mesure que la création avance, des anomalies apparaissent et cette façade commence à se fissurer.

L’étape des Tribus doit représenter un nouveau seuil.

Jusqu’ici, le système observait essentiellement le personnage humain.

Ici, quelque chose de plus ancien commence à l’observer.

L’interface peut donc encore conserver des traces de son apparence administrative, mais elle doit commencer à être contaminée par une esthétique plus organique, spirituelle et totémique.

Il ne faut pas basculer brutalement dans une page fantasy classique.

Le charme vient du contraste :

- structure encore propre et rationnelle ;
- éléments visuels progressivement impossibles ;
- symboles qui semblent apparaître sous l’interface ;
- sensation que le logiciel tente encore de classifier quelque chose qu’il ne comprend plus vraiment.

---

# 3. Structure générale de l’expérience

L’expérience peut être divisée en quatre moments.

## Moment A — Le questionnaire

Le joueur répond à une courte série de situations ou dilemmes.

L’interface reste encore relativement familière.

Chaque question apparaît seule afin de conserver un rythme narratif.

Pas de jauge « Black Fury +3 / Silver Fang +1 ».

Le scoring reste totalement invisible.

Une progression discrète peut exister, mais éviter quelque chose de trop scolaire comme :

> Question 3/7

Préférer quelque chose de plus intégré :

> Évaluation comportementale — séquence en cours

ou une simple progression graphique.

Les questions doivent donner l’impression qu’on analyse la personne, pas qu’on lui demande directement quelle philosophie elle préfère.

---

# 4. Transition après la dernière réponse

C’est ici que l’interface doit devenir mémorable.

Après validation de la dernière réponse :

l’écran ne doit pas immédiatement afficher :

> Vos résultats

Pendant quelques instants, le système semble effectuer une analyse normale.

Exemples de texte :

> Analyse des réponses…

Puis quelque chose déraille subtilement.

Certaines lignes administratives disparaissent.

Le vocabulaire change.

Par exemple :

> Analyse comportementale…

devient :

> Correspondances détectées…

puis :

> Résonances détectées…

Puis finalement :

> Quelque chose vous a remarqué.

La transition doit être lente mais courte.

Pas de long écran d’attente artificiel.

Surtout : **aucun effet de curseur ou texte tapé caractère par caractère.**

---

# 5. L’écran des affinités

Au lieu d’arriver directement sur une grille classique de 13 cartes, commencer par une composition plus spectaculaire.

## Concept : le Cercle des Treize

Les treize Tribus apparaissent sous forme de symboles / sceaux / marques totémiques répartis autour d’un cercle ou dans une constellation organique.

Toutes sont visibles.

Mais les affinités principales semblent « répondre ».

Elles peuvent :

- être légèrement plus lumineuses ;
- se déplacer légèrement vers l’avant ;
- présenter une pulsation discrète ;
- posséder une texture ou une aura plus présente ;
- faire apparaître le nom de la Tribu plus clairement.

Les autres restent parfaitement accessibles.

L’objectif n’est pas de dire :

> celles-ci sont bonnes, les autres sont mauvaises.

Mais plutôt :

> certaines ont répondu plus fortement.

Le cercle peut être accompagné d’un texte :

> Vos réponses ne désignent pas une Tribu.
>
> Elles révèlent simplement certaines affinités.

Puis :

> Trois voix semblent répondre plus nettement que les autres.

Le nombre peut être adaptable selon les scores.

---

# 6. Ne pas afficher des pourcentages trop précis

Éviter :

> Silver Fangs — 87 %
> Shadow Lords — 64 %

Ce type de chiffre donne une fausse impression de diagnostic scientifique.

Préférer des niveaux qualitatifs :

- Résonance très forte
- Résonance forte
- Résonance sensible
- Résonance faible

Ou encore quelque chose d’un peu plus diégétique :

- Vous appelle
- Vous reconnaît
- Vous observe
- Reste distante

Mais il faut éviter que la formulation devienne trop déterministe.

Une solution intermédiaire serait :

**Affinité détectée : très forte**

---

# 7. Passage du Cercle aux cartes

Sous le Cercle des Treize se trouve l’accès à :

> Explorer les Tribus

Le joueur arrive alors sur la vraie interface de choix.

Les 13 Tribus sont présentes.

Aucune n’est masquée.

Aucune n’est grisée uniquement parce que son affinité est faible.

Les Tribus les plus compatibles apparaissent d’abord ou possèdent une mise en valeur visuelle.

On peut organiser la grille ainsi :

### Vos principales affinités

Les 2 ou 3 cartes ayant obtenu les meilleurs résultats.

Puis :

### Toutes les Tribus

Les treize cartes.

Les Tribus déjà affichées dans la première zone peuvent également apparaître ici afin que la seconde section reste réellement exhaustive.

---

# 8. Design des cards

Chaque card doit permettre de comprendre la Tribu sans ouvrir immédiatement une énorme fiche.

Structure possible :

**Nom de la Tribu**

Totem

Une phrase manifeste très courte.

Exemple conceptuel :

> « Une responsabilité héritée n’est pas un privilège. C’est une dette. »

Puis :

- philosophie dominante ;
- rapport au monde ;
- une ou deux tensions internes ;
- affinité détectée.

En bas :

> Découvrir la Tribu

La carte ne doit pas uniquement vendre une esthétique.

Le joueur doit immédiatement comprendre :

> « Qu’est-ce que cela signifie d’être membre de cette Tribu ? »

---

# 9. Fiche détaillée d’une Tribu

Cliquer sur une carte ouvre un panneau, une page ou un grand drawer.

Cette fiche peut contenir :

## Identité

Quelques paragraphes courts expliquant la philosophie.

## Ce que cette Tribu défend

3 à 5 notions fortes.

## Ses contradictions

Partie très importante.

Exemple :

> Les Silver Fangs considèrent que le commandement impose une responsabilité exceptionnelle. Cette conviction peut produire des chefs capables de se sacrifier pour les leurs… ou des aristocrates persuadés que leur naissance suffit à justifier leur autorité.

Cela évite les descriptions caricaturales.

## Totem

Nom, fonction symbolique et relation avec la Tribu.

## Particularités de création

Exemple :

> Pure Breed 3 minimum.

ou :

> Cette Tribu n’accepte normalement pas les Homid.

Ces informations doivent être visibles mais ne doivent pas transformer immédiatement la carte en erreur système.

## Dons possibles

Afficher les Dons de départ disponibles avec une description très courte.

L’objectif est aussi de permettre au joueur de penser :

> « La philosophie m’intéresse, et les pouvoirs me donnent envie de la jouer. »

C’est un critère parfaitement légitime.

---

# 10. Restrictions de création

Une règle de lore ne doit pas nécessairement masquer une Tribu.

Si un personnage ne satisfait pas normalement une condition :

afficher la Tribu malgré tout.

Mais ajouter clairement :

> ⚠ Choix non standard pour ce personnage.

Puis expliquer pourquoi.

Exemple :

> Les Red Talons n’acceptent normalement pas les Homid dans W20.

Puis :

> Ce choix nécessite une validation du MJ.

L’objectif est de préserver la connaissance du jeu et la liberté de discussion.

---

# 11. Sélection finale

Le joueur peut sélectionner n’importe laquelle des 13 Tribus.

Même avec une affinité faible.

Lorsque le choix correspond à une forte affinité, le système peut simplement constater :

> Cette Tribu faisait partie de vos résonances les plus fortes.

Lorsque le joueur choisit une Tribu très éloignée de son profil :

ne pas le décourager.

On peut afficher quelque chose comme :

> Cette Tribu n’était pas parmi celles ayant le plus fortement réagi à vos réponses.
>
> Cela n’empêche absolument pas votre personnage de vouloir suivre cette voie.

Puis :

> Confirmer ce choix

Le système ne doit jamais donner l’impression que le joueur « joue mal son personnage ».

---

# 12. Confirmation narrative

Après validation définitive :

éviter :

> Tribu enregistrée avec succès.

À ce stade, la façade administrative doit commencer à céder.

Le texte peut devenir beaucoup plus évocateur.

Exemple conceptuel :

> Quelque chose répond.

Puis le symbole du Totem apparaît.

Ou :

> Votre choix a été entendu.

La transition suivante peut alors préparer l’étape spirituelle suivante de la création.

---

# 13. Direction artistique

Le design doit rester cohérent avec l’évolution générale du site.

## Début du questionnaire

- interface encore structurée ;
- typographie propre ;
- géométrie corporate ;
- panneaux nets ;
- faible présence du surnaturel.

## Fin du questionnaire

Progressivement :

- textures organiques ;
- légères déformations ;
- symboles visibles derrière certaines surfaces ;
- ombres impossibles ;
- halos très discrets ;
- imperfections dans les lignes et cadres.

## Écran des Tribus

L’interface administrative est encore reconnaissable, mais quelque chose d’ancien est désormais clairement présent.

Le résultat ne doit pas ressembler à un menu de RPG fantasy standard.

Éviter :

- cartes couleur par classe ;
- icônes génériques fantasy ;
- ornementation médiévale ;
- grosse esthétique parchemin.

Chercher plutôt :

**occultisme contemporain + interface qui se désagrège + spiritualité animiste.**

---

# 14. Animation

Les animations doivent être lentes, discrètes et organiques.

Exemples :

- très légère respiration d’un symbole ;
- apparition d’une texture sous une card au hover ;
- mouvement presque imperceptible d’une aura ;
- déplacement doux lorsque les affinités principales remontent ;
- réaction légère d’un sceau lorsqu’on le survole.

Éviter les animations « jeu vidéo UI » trop démonstratives.

Et surtout :

**aucun effet de texte tapé / curseur de machine à écrire.**

---

# 15. UX mobile

L’expérience doit être pensée pour fonctionner parfaitement sur téléphone.

Le Cercle des Treize peut devenir :

- un arc horizontal scrollable ;
- une constellation navigable ;
- ou une disposition verticale plus simple.

Ne jamais sacrifier la lisibilité pour conserver la composition desktop.

Les cards doivent rester suffisamment grandes pour :

- lire le nom ;
- comprendre la philosophie ;
- identifier l’affinité ;
- ouvrir facilement le détail.

Le détail d’une Tribu peut devenir une feuille plein écran sur mobile.

---

# 16. Accessibilité

Les affinités ne doivent jamais être communiquées uniquement par une couleur ou une luminosité.

Toujours accompagner la mise en valeur d’un texte :

> Affinité forte

Les animations doivent respecter `prefers-reduced-motion`.

Les cartes doivent être navigables au clavier.

Les informations importantes doivent conserver un contraste suffisant malgré l’esthétique sombre ou organique.

---

# 17. Modèle fonctionnel

Le système doit séparer clairement :

### scoring

Calcule les affinités à partir des réponses.

### présentation

Décide comment les affinités sont affichées.

### choix final

Enregistre explicitement la Tribu choisie par le joueur.

Ces trois données ne doivent jamais être confondues.

Exemple :

```text
tribeAffinity = {
  silverFangs: 18,
  shadowLords: 12,
  childrenOfGaia: 9,
  ...
}

suggestedTribes = [
  "silverFangs",
  "shadowLords",
  "childrenOfGaia"
]

selectedTribe = "childrenOfGaia"
```

Le joueur peut donc avoir :

> affinité principale : Silver Fangs

tout en choisissant :

> Children of Gaia

C’est un comportement parfaitement normal et prévu par le système.

---

# 18. Principe essentiel

Le questionnaire ne doit jamais chercher à répondre à :

> « Quelle est ta Tribu ? »

Il doit répondre à :

> « Quelles visions du monde semblent résonner avec ton personnage ? »

Puis le jeu rend la décision au joueur.

Le résultat idéal est que le joueur découvre éventuellement une Tribu à laquelle il n’aurait pas pensé, lise trois ou quatre fiches, hésite réellement… puis choisisse celle qu’il a envie d’incarner.

Cette hésitation est une réussite UX, pas un échec du test.
